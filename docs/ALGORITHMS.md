# 凡人修仙：核心算法与升级指南

本文描述当前实现实际执行的规则，基准为 2026-10-10 读取的原版公开脚本：
<https://4m0qygtsyawf3.aiforce.cloud/app/app_17dt3bhhbyg/game.js>

目标是保留功能、数值、概率与计算顺序，独立优化界面。本机排行榜替代原版的网络请求及失败回退。核心未修正原版潜在的数值问题，避免无意改变平衡。

## 1. 技术与文件边界

- `src/core/data.js`：灵根、境界、突破表、寿命表、仙人信物、成就和常量。
- `src/core/events.js`：21 种事件，年龄限制、权重、次数、条件与结果。
- `src/core/simulator.js`：无 DOM、无存储的模拟器；`createSimulator(random)` 可注入随机源。
- `src/types.ts`：角色、日志、历史和排行榜的 TypeScript 类型。
- `src/storage.ts`：浏览器存储；沿用原版键名和记录形状。
- `src/main.ts`：界面、播放调度、结算、成就及本机排行。
- `tests/fixtures/original-core.txt`：原版核心快照，仅供对照测试，未运行原站平台 SDK。
- `tests/core.test.js`：相同随机序列下的新旧核心对照。

选择 Vite + TypeScript。核心暂时保留 JavaScript 的原始计算语义，UI 用严格 TypeScript。HTML 本身并不阻碍升级；关键在于数据、模拟、持久化和展示是否分离。无框架适合当前小型单页游戏，后续可在不更换模拟器的情况下接入 Vue/React 或服务端。

## 2. 状态与初始角色

| 字段 | 意义 |
| --- | --- |
| innate | 先天灵根档位；灵根异变事件会改写它 |
| aptitude | 当前资质，决定突破与修为系数，可经事件提升 |
| lvl | 层级 1～100；101 为仙人 |
| cult | 修为，与层级分别记录；并非升级经验条 |
| lifespan | 当前寿命上限，并非剩余行动点 |
| age / year | 当前年龄 / 模拟年数 |
| xinwu | 仙人信物数组，正常规则最多一个 |
| maxCount | 每个事件剩余次数；未记录时使用事件默认次数 |
| ascended / dead | 飞升 / 死亡标记 |
| ascendMode | xianyuan、feisheng、xiandi 或 fail |
| deadCause | age 或 accident；某些死亡事件不设置此字段 |
| gotXitong / gotYibian | 系统与灵根异变成就标记 |

开局先抽灵根，再初始化修为 `整数均匀随机[innate, innate×10]`，寿命 `整数均匀随机[60,100]`，年龄 6，层级 1，其余计数与标记清零。

境界依次为炼体、练气、筑基、结丹、元婴、化神、炼虚、合体、大乘、渡劫，每境十层。

`境界序号 = floor((lvl−1)/10)+1`；`小层 = ((lvl−1)%10)+1`。

## 3. 随机源与一致性的范围

连续均匀随机 `rand(a,b)=a+random()×(b−a)`，整数均匀随机 `irand(a,b)=floor(rand(a,b+1))`，取整使用 JavaScript `Math.round`。

正式游戏默认使用 `Math.random`。测试注入确定性随机序列，同时运行原版核心与新核心，比较逐年状态与日志。

“一致”指相同初始状态、加成、模拟调用及随机输入下得到相同结果，以及正式游戏使用相同概率规则；不承诺和正在运行的原网站逐点击得到相同人生。原版没有保存随机种子，且视觉粒子与抽签动画也会消耗全局随机数。本版动画不消耗模拟随机数。

## 4. 灵根抽取与跨局加成

| 档位 | 灵根 | 基础权重 | 修为系数 |
| --- | --- | ---: | ---: |
| 1 | 伪灵根 | 33 | 1 |
| 2 | 杂灵根 | 25 | 1.5 |
| 3 | 四灵根 | 11 | 2.2 |
| 4 | 三灵根 | 9 | 3.2 |
| 5 | 双灵根 | 7 | 4.5 |
| 6 | 异灵根 | 5 | 6.3 |
| 7 | 地灵根 | 4 | 8.8 |
| 8 | 天灵根 | 3 | 12 |
| 9 | 灵体 | 2 | 16 |
| 10 | 仙体 | 1 | 22 |

基础权重合计 100。低阶 1～5 权重 85，高阶 6～10 权重 15。

```text
p = 0.15 + max(0, playerLv)×0.001 + followBonus/100 + achievementBonus/100
高阶新总权重 = 85×p/(1−p)
高阶各档新权重 = 基础权重×高阶新总权重/15
低阶各档权重保持不变，最后按全部权重抽签
```

加成是百分点，不是乘算。没有新增关注加成入口；`followBonus` 沿用原版默认 0。原版没有对 `p >= 1` 进行限制，本版保留；若未来支持极高玩家等级，应作为单独平衡改动处理。

## 5. 每年的严格结算顺序

`rollYear(g)` 不主动拒绝已经结束的角色；调用方保证只推进存活且未飞升的角色。

1. `year++`，`age++`。
2. 仙帝传承抽签；成功直接飞升并返回。
3. 神秘系统抽签；成功将当前资质设为 10、寿命 +50，设置标记。
4. 层级 ≥91 且尚无信物，抽取仙人信物。
5. 未满 100 层时尝试突破，可连续突破。
6. 按 `50/lifespan` 抽取平稳修行收益。
7. 满 100 层且剩余寿命 ≤10，判定仙缘或成仙劫，随后返回。
8. 若 `age > lifespan`，寿尽死亡并返回。
9. 按 `30/lifespan` 抽普通事件。
10. 若事件后 `age > lifespan`，设置意外死亡。

顺序影响寿命、抽签次数、飞升时点与事件结果；重构时不可随意交换。

## 6. 突破概率

| 杂灵根 | 2 | 10 | 25 | 60 | 150 | 400 | 1000 | 2000 | 5000 | 8000 | 12000 | 15000 |
| 四灵根 | 1.3 | 6.7 | 17 | 40 | 100 | 267 | 667 | 1333 | 3333 | 5333 | 8000 | 10000 |
| 三灵根 | .95 | 4.8 | 12 | 29 | 71 | 190 | 476 | 952 | 2381 | 3810 | 5714 | 7143 |
| 双灵根 | .8 | 4 | 10 | 24 | 60 | 160 | 400 | 800 | 2000 | 3200 | 4800 | 6000 |
| 异灵根 | .65 | 3.2 | 8.1 | 19 | 48 | 129 | 323 | 645 | 1613 | 2581 | 3871 | 4839 |

年龄系数按顺序判断：年龄 ≤12 为 1.2；≤18 为 1.1；否则年龄 >寿命×0.8 为 0.9；其余为 1。

基础年度概率 `b=1/分母×年龄系数`。

- `b ≤ 0.25+1e−9`：只抽一次，成功升一层。
- `b > 0.25+1e−9`：进入连破循环，每步根据新的层级重新查表，再乘 `0.6^step`。
- 重新查表概率或衰减概率 ≤上述阈值时直接停止，**不再补一次低概率突破抽签**。
- 任一步失败即停止；到 100 层停止；年龄系数在整次突破中固定。
- 概率超过 1 时未截断，但与 `[0,1)` 随机数比较自然必成。

## 7. 突破修为与寿命

令 `C` 为资质修为系数，`L` 为突破后的新层级：

```text
L < 91:       round(C×(0.6L + rand(−0.4L,0.4L) + 6))
91 ≤ L ≤ 99:  round(C×(0.6L + rand(−0.4L,0.4L) + 20))
L ≥ 100:      round(C×(1.2L + rand(−200,200) + 200))
```

已处于 100 层时，事件调用一次 `levelUp` 不再升层，改为修为 +10000，无寿命收益。

寿命增量表按 `floor((新层级−1)/10)` 取值：

| 新境界 | 练气 | 筑基 | 结丹 | 元婴 | 化神 | 炼虚 | 合体 | 大乘 | 渡劫 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 整数随机范围 | 20–30 | 80–100 | 200–240 | 400–500 | 800–1000 | 1000–1200 | 1500–1800 | 2400–3600 | 4000–6000 |

新层级 `%10==1` 且 >1，获得完整抽取值；同境其他层级仅获得 `round(抽取值×0.01)`。炼体层内没有寿命增量。

平稳修行每年触发概率 `50/lifespan`，增加：
`round(max(cult×rand(0.001,0.0015), rand(5,10)))`。

### 仙界残境的蒙特卡洛门槛

条件为 `cult > testCult(8,age,20,15) || lvl > testLv(8,age,20,15)`，逻辑 OR 短路。

每次门槛计算：开启测试模式，模拟20个角色，创建后将先天与当前资质指定为8；初始修为仍来自创建时原先抽到的灵根。推进到当前年龄、死亡、飞升或10000步，收集修为/层级并排序。取 `floor(20×(1−15/100))=17` 下标，即第18个值。测试模式排除仙界残境自身，避免递归。

注意：这里是两个可能独立运行的模拟批次；不是同一批角色同时比较两项指标。模拟也消耗随机数，并受到当前灵根加成影响。不能随意改为缓存阈值、固定阈值或近似公式。

## 9. 飞升

### 成仙劫

满100层、剩余寿命≤10时判断。没有信物或信物未达标时，按修为 `c` 抽签：

```text
c < 100000:       0.0001
100000 ≤ c <250000: 0.001 + ((c−100000)/150000)×0.009
250000 ≤ c <500000: 0.01 + ((c−250000)/249999)×0.09
c ≥500000:        1
```

分母 `249999` 原样保留；10万和50万处存在跳变。成功：`cult=round((1000000+cult)×rand(1.15,1.45))`，层级101、寿命999999、标记飞升。失败立即死亡。

### 仙人信物

层级≥91、尚无信物时，每年概率0.00003；命中后10种等概率选取一个。到常规飞升时点且修为达到该信物门槛，必定仙缘飞升；否则记录未达标日志，转成仙劫。信物本身不会提前触发飞升。

### 隐藏机缘

神秘系统概率5e−9/年：当前资质10，寿命+50，记录成就标记；不改先天灵根，不限制重复触发。

仙帝传承概率5e−10/年：直接飞升，修为 `round((1000000+cult)×2)`，不要求境界或寿命条件。

## 10. 结算、经验和成就

- 每次结算总局数+1，飞升时飞升次数与累计飞升次数+1。
- 飞升经验1000；普通死亡经验 `round(lvl×0.5)`；提前结算经验 `round(lvl×0.1)`。
- 当前等级升级需要 `50×(lv+1)` 经验；扣掉后升级，循环处理多级提升。
- 每局结算删除当前存档，写入历史，再检查角色成就。
- 成就一经解锁永久保留，其 bonus 数字表示百分点。

## 11. 调度、存档与本机排行榜

正常间隔400ms，慢速800ms。每次展示批次内部不断 `rollYear`，直到出现非空日志、角色结束或达到200000步保护上限。并非每个间隔只过一年。

当前纪事显示最多300条，本局完整日志用于结算回顾。手动存档保留角色状态、时间与最近80条日志；继续修炼使用存档日志，不重建丢失的旧日志。

| localStorage键 | 内容 |
| --- | --- |
| fc_player | 玩家等级和经验 |
| fc_ach | 已解锁成就 |
| fc_feisheng_total | 累计飞升次数 |
| fanren_sim_stats | 本机局数和飞升统计 |
| fc_history | 最近100局结算记录 |
| fc_rank | 本机飞升榜前100条 |
| fc_save | 当前手动存档 |

本机排行榜仅飞升角色可提交，名字去首尾空白后截取8个JavaScript字符单元；按未格式化 `cultNum` 降序排列，截前100。每次结算只能提交一次。不发送网络排行请求。低于前100时如实提示未入榜，修正原版回退路径中可能显示“第1名”的提示问题，不改变排序规则。

存档键兼容不代表跨域迁移。浏览器按网站来源隔离存储，新站不会自动读到原站存档；当前版本没有新增导入导出功能。

## 12. 已知原版行为与未来改动边界

1. “灵根进化”没有修改资质；“灵根异变”同时改写先天和当前资质。
2. 仙界残境失败设置dead，不设置deadCause；可能在结算标题显示“与世长辞”，日志仍说明死亡原因。
3. 寿尽判断是严格大于，不是大于等于。
4. 高阶概率无上限保护；如拓展高等级，需明确修改规则和测试。
5. 信物、系统和传承的概率均为年度概率，不是单局概率。
6. “满100人开放仙界模拟器”只是一句进度提示，原版公开代码未包含仙界模拟引擎。本版保留提示，不新增玩法。
7. `FEISHENG_CHANCE` 常量保留，但实际成仙劫由分段函数决定，不应误用此常量替代。
8. UI 使用更直观的中文状态与排版，存档失败、未进榜等提示如实反馈；核心数值与事件日志保留。

后续增加玩法建议先确定是否属于“表现变更”或“规则变更”。表现变更应保持核心对照测试全通过；规则变更建立独立版本和明确的差异测试，再决定存档迁移。新增事件至少定义年龄、次数、权重、条件与成功/失败后果，评估是否改变原事件池概率；新增网络排行榜可替换持久化边界，不应直接改模拟公式。
